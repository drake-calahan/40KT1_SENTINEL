## Pourquoi ce lot existe

`docker events` (wodle `docker-listener`, lot `P01.8`) **ne porte pas**
`privileged`, les montages, ni les ports publiés. Les trois cas « conteneur
`--privileged` », « `docker.sock` monté », « port sur `0.0.0.0` » (celui que
`ufw` ne voit pas) sont donc **invisibles** depuis les règles Wazuh sur ce flux.
Une règle qui prétendrait les attraper serait un faux vert silencieux.

## Périmètre

1. **`scripts/inspection_docker.py`** — sonde en lecture seule :
   - appelle `docker` en local (pas de daemon config) ;
   - rend **`ok` / `ko` / `unknown`** (jamais `ok` faute de mesure) ;
   - codes de sortie : `0` = ok · `1` = ko · `2` = unknown ;
   - signale chaque conteneur fautif (nom + motif), sans remédier.
2. **Unités** `sentinel-inspection-docker.service` + `.timer` **posées dans le
   dépôt, désarmées** : ni enable, ni start dans ce lot.
3. **Tests** : majorité sur la dégradation (`docker` absent, inspect illisible,
   JSON tronqué → `unknown` ; privileged / socket / `0.0.0.0` → `ko`).

## Hors périmètre

- Configurer le démon Docker ou Compose (HQ).
- Règles Wazuh sur `docker events` pour ces trois cas.
- Envoi Discord / ntfy (`P02.0`).
- `responder/`.

## Critères d'acceptation

1. `ruff check` + `ruff format --check` verts.
2. `pytest` vert, dont au moins trois cas `unknown` / `ko`.
3. Aucune unité activée ; préfixe `sentinel-*`.
4. Aucun `*_enabled: true` dans le dépôt.
